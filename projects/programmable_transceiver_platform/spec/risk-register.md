# Transceiver risk register

The single risk register for the GF180 programmable transceiver, two chips (`pt_rf`, `pt_wired`; `spec/chips.json`). Other documents cite these IDs and keep no risk lists of their own.

**220 risks:** open 133, demanded-mitigation 58, risk-accepted 11, mitigated 12, closed 6. By chip: rf 83, wired 45, both 92. Open or demanded with no active owner: 55.

**Status:** *open* = unresolved or analysis pending; *demanded-mitigation* = a fix is demanded and not yet proven; *risk-accepted* = the residual is accepted; *mitigated* / *closed* = kept only because the row records a rule that must keep being obeyed. **Score** = likelihood × impact (each 1–5). **Chip** = `rf` (`pt_rf` only), `wired` (`pt_wired` only), `both` (shared block, RTL, pad ring, package or board). **Active** = whether the first-named owner has an agent working today (active: pads, wired RX + timing rings, RF RX, digital, wired TX, bias / power delivery, chip assembly, coordinator; not active: LO synthesis, RF TX, converters, observation / debug, board / FPGA / bring-up). Rows are sorted open and demanded first by score, then accepted, mitigated, closed.

To add a risk: append a row with the next free number in its prefix, a score, chip, status, mitigation/owner and one evidence path (`scratch/` paths are relative to the repository root, others to this project). Change status in place; delete a row when its fix is fully embodied in the design and leaves no standing rule. IDs are never reused; *aka* lists merged IDs.
